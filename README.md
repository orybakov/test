# ◈ Voice Sentinel

**Локальный диспетчер умных голосовых уведомлений** для Whop, Codex, trading-агентов, homelab и любых HTTP-источников. Получает события, фильтрует шум, группирует обычные сообщения в дайджест, озвучивает важные и при настройке отправляет их в Telegram. Веб-панель на русском.

- Без облака и API-платежей по умолчанию: правила классификации + Web Speech API на компьютере.
- **Опционально**: Qwen3-TTS-12Hz-0.6B-CustomVoice на NVIDIA GPU для локального WAV и голосовых Telegram.
- **Опционально**: любая OpenAI-совместимая LLM (CLIProxyAPI, Ollama и др.) для умной краткой формулировки и классификации.
- SQLite/WAL, дедупликация внешних ID, защита API-ключом, хранение истории.

> Статус: **MVP**. Тесты проверяют HTTP API, правила и доставку без модели. GPU-инференс и Telegram необходимо проверять на конечной машине с доступом к устройствам и токенам.

## Запуск на Arch Linux / Docker

Требуются Docker с плагином Compose и Python 3 (для первого создания ключа; при отсутствии Python используется `openssl`).

```bash
./start.sh
```

Открой **http://127.0.0.1:8099**, вставь API-ключ, выведенный командой. Нажми **«Проверить уведомление»**, затем **«Озвучивать на этом устройстве»**. API-ключ хранится в `sessionStorage` вкладки, не в коде и не в репозитории. Веб-озвучка запускается после разрешённого пользовательского действия; вкладка должна быть открыта.

Проверка события из консоли (автоматически читает `.env` в каталоге проекта):

```bash
python3 scripts/notify.py whop "Публикация не прошла" "Instagram требует подтверждения" --level important --event-id ig-101
python3 scripts/notify.py codex "Тесты прошли" "Все 175 тестов зелёные"
```

Сервер привязан к **127.0.0.1**, извне сети не доступен. На другом компьютере используй SSH-туннель, VPN или защищённый reverse proxy с дополнительной аутентификацией. Не публикуй порт напрямую в интернет. Для доступа из Docker-контейнеров одного хоста используй общую Docker-сеть или безопасный адрес хоста; API остаётся защищён ключом.

## Настоящий Qwen3-TTS с русским голосом (опционально)

Нужен драйвер NVIDIA + `nvidia-container-toolkit` с рабочим `docker run --gpus all ...`. На RTX 4070 Ti начать с модели **0.6B**. Браузерный fallback работает даже когда Qwen ещё не запущен, не скачан или не помещается в VRAM.

```bash
./start.sh --qwen
# первая сборка скачает тяжёлые CUDA/PyTorch зависимости; при первом запуске — веса модели
# следить за моделью:
docker compose --profile qwen logs -f tts
```

Настроить голос `TTS_VOICE=Ryan` или `Vivian` в `.env` (модель поддерживает 9 встроенных тембров; русская речь возможна с любым, качество зависит от голоса). Можно переключить `QWEN_MODEL=Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`, но потребуется больше VRAM; **никаких гарантий скорости без измерений**. В 0.6B нет управления инструкциями эмоциональности.

Qwen — отдельный сервис без публичного порта. В ответ на события он генерирует WAV, а основной контейнер перекодирует его в OGG/Opus через FFmpeg и отправляет `sendVoice` в Telegram. Если Qwen временно недоступен, уведомление сохранится в панели и Telegram получит текст.

Откат к браузерному синтезу:

```bash
sed -i 's/^TTS_PROVIDER=.*/TTS_PROVIDER=browser/' .env
docker compose up -d --build
docker compose --profile qwen stop tts
```

## Telegram

Создай бота через @BotFather, напиши ему любое сообщение, узнай chat ID через официальный Telegram Bot API `getUpdates`. Укажи локально в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен из BotFather>
TELEGRAM_CHAT_ID=<личный chat ID>
```

Затем: `docker compose up -d --force-recreate sentinel`. **Не коммить `.env`.** Если Qwen отключён, Telegram получает только текст; если включён — текст + голосовое сообщение (OGG/Opus). Для частных диалогов бот должен получить первое сообщение от пользователя.

## LLM-классификатор (опционально)

В `.env`:

```dotenv
LLM_BASE_URL=http://host.docker.internal:8317/v1
LLM_MODEL=gpt-6.1-sol
LLM_API_KEY=<API key локального шлюза>
```

Затем пересоздай контейнер. Значения здесь **пример**; порт, имя модели и ключ должны соответствовать твоему CLIProxyAPI. В Linux Docker доступ к host.docker.internal зависит от настроек сети; альтернативно используй доступный hostname внутри Docker-сети. LLM не выполняет команды, только создаёт короткий JSON. При недоступности модели используются локальные правила. **Внешним API будет отправляться текст события**, поэтому не включай облачный шлюз для событий с паролями и секретами.

## Интеграция с проектами

HTTP API: `POST /api/events`, заголовок `X-API-Key: <содержимое SENTINEL_API_KEY>`, JSON:

```json
{
  "source": "whop",
  "event_id": "job-772-publish",
  "title": "Instagram не опубликовал клип",
  "message": "Нужна ручная проверка профиля",
  "level": "auto"
}
```

`source` — имя агента, `event_id` — стабильный ID для дедупликации. `level`: `auto`, `critical`, `important`, `normal`, `silent`. Два события с одинаковыми `source` + `event_id` сохраняются один раз. Повторные события без `event_id` считаются новыми.

Эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | локальный healthcheck (без авторизации) |
| POST | `/api/events` | принять событие |
| GET | `/api/events` | история, метрики и каналы |
| GET | `/api/events/{id}/audio` | скачать WAV с API-ключом |
| POST | `/api/demo` | тестовое событие |
| POST | `/api/digest` | объединить накопленные обычные события |

Автоматический дайджест: `DIGEST_INTERVAL_SECONDS=3600` (по умолчанию каждый час работы процесса). Статусы `queued`, `ready`, `silent`, `digest`, `digested`. Ошибки TTS и Telegram видны в панели, чтобы событие не пропало.

## Ограничения v0.1

- Встроенные правила — не полноценное AI-понимание; умное суммирование требует LLM.
- Озвучка в браузере зависит от установленных системных голосов и политик autoplay.
- Веб-панель показывает последние 60 событий, полная история сохраняется в SQLite.
- Для Telegram нужны собственные бот-токен и chat ID. При сбое Telegram сообщение остаётся в UI с ошибкой; автоматическое повторное отправление в MVP не предусмотрено, чтобы не допускать дублей.
- Нет готовых патчей к production-проектам: интеграция осуществляется отдельными webhook-вызовами.
- Публикация кода в GitHub не запускает локальный сервис; его запускает `./start.sh` на твоём Arch/Docker-хосте.

Модель: [QwenLM/Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS). Проект не включает веса, ключи или чужой код модели.
